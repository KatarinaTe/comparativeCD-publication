# Conversion notes — 03_qc

Decisions and discrepancies noted while converting this stage's original scripts into the
Nextflow pipeline under `code/03_qc/`. Moved out of `code/03_qc/README.md` so that file documents
only the pipeline itself.

## Resolved Issues from Original Implementation

### `bcftools filter -i 'PASS'` is very likely non-functional

In `1_High_LowPass/high_vs_lowpass.sh`, the original ran `bcftools filter -i 'PASS'` immediately
followed by `bcftools view -f 'PASS'` into the same output filename. `-i/--include` takes a
boolean expression — documented and real-world usage always writes `FILTER="PASS"` (field `=`
value); a bare literal `'PASS'` is very likely invalid or a no-op. `-f/--apply-filters PASS` is
the correct, standard way to restrict to PASS sites and is almost certainly what produced the
archived output. `FILTER_PASS_VCF` implements only the working `-f` form.

### Downsampling study deliberately covers 10 dogs, not 11

`3_Downsampling/1_create_downsampled_bams.sh`'s own comments record that sample `SRR13340529`
was accidentally omitted partway through the original manual run ("obs I missed sample
SRR13340529 - so starting with 11 samples ended up with 10 downsampled samples"). This pipeline
reproduces the 10-sample set that was actually analyzed and reported (`samples_downsampling_10`),
rather than "fixing" the omission by including the 11th sample — the goal here is a faithful
reproduction of the published analysis, not a corrected rerun.

### `2_mapping&imputing&depth_bams.sh` reuses `01_mapping`'s processes, not new ones

The original downsampling re-mapping/re-imputation script (`3_Downsampling/2_mapping&imputing&depth_bams.sh`)
initially appeared to depend on scripts missing from this repository. Two were later confirmed to
already exist: `data/03_qc/dog10k_mapping_start_at_bams.sh` is the same script behind
`DOG10K_MERGE_MARKDUPS_BQSR_GVCF` in `01_mapping` (with the `bwa-mem2` alignment step skipped,
since the downsampled input is already an aligned BAM), and
`code/original_source/01_mapping/3_LowPass_imputation/scripts/03_ImputeAndPhaseChrsByChunks.sh`
is the literal source of `GLIMPSE_IMPUTE_CHUNKS`. Study 3 therefore reuses `01_mapping`'s GLIMPSE
processes, forked (`MERGE_BQSR_GVCF_DOWN`, `GLIMPSE_*_DOWN` in `process_definitions.nf`) with a
`meta` (fraction) value threaded through every tuple so all 10 fractions run through one call each
instead of ten — see that file's header for why these are forks rather than a shared include.

### Axiom-vs-LowPass MAF exclusion split out of `bcftools isec`

The original `2_Axiom_LowPass/axiom_vs_lowpass.sh` embedded `-e'MAF<0.01'` directly in the
`bcftools isec` call (which applies the exclusion to both inputs before intersecting). Here it is
an explicit `MAF_FILTER_VCF` step applied to both VCFs before `ISEC_COMMON_SITES`, matching how
study 1 already structured the equivalent step — same result, one shared, plain two-file
`ISEC_COMMON_SITES` process instead of a filter-aware variant.

### Downsampling concordance uses pre-QC-filter genotypes — preserved, not corrected

`3_Downsampling/2_mapping&imputing&depth_bams.sh`'s QC-filter step (Step 5) reads the ligated,
merged VCF (`Down_<fraction>.<chr>.merged.vcf.gz`) and writes a new, separate file
(`Down_<fraction>.<chr>.merged.qc_modi.vcf.gz`) alongside it — the original is not overwritten.
`3_genotype_concordance.sh`'s own concat step then globs
`Down_<fraction>.chr{1..38}.merged.vcf.gz` — the **pre**-QC-filter file, not the `qc_modi` one —
even though its output is named `...ALLCHR.merged.qc_modi.vcf.gz`, implying QC-filtered content.
Read literally, the original downsampling concordance metric was computed against **all**
imputed genotypes regardless of GLIMPSE INFO score, not just the INFO≥0.8 subset the QC-filter
step (which still runs, per Step 5) produces. `IMPUTE_DOWNSAMPLED_FRACTIONS` reproduces this
literally: `GLIMPSE_QC_FILTER_DOWN` still executes, but `CONCAT_CHR_VCFS` consumes
`BCF_VCF_DOWN`'s pre-filter output, matching the original concat command rather than "correcting"
it to use the QC-filtered file the output name implies.
